# 工作经历STAR面试笔记

## 项目一：新东方在线｜测试平台开发（接口巡检 + APP UI自动化巡检 + 内部提效工具）
**S 情境**：
团队回归测试工作量大，移动端APP、H5版本迭代频繁，每次版本上线需要大量人工回归接口以及页面功能，重复工作多，测试人力消耗高。

**T 任务**：
参与开发内部测试平台，实现接口自动化巡检、APP UI自动化巡检；开发多款小工具提升团队测试效率，降低回归成本，保障迭代版本质量。

**A 行动**：
1. 使用Java/SpringBoot搭建平台后端，完成接口用例管理、定时巡检任务、报告生成模块开发；
2. 对接Appium实现APP UI自动化任务调度，支持用例批量执行、执行结果回显；
3. 封装团队高频使用的小工具，比如数据构造工具、日志解析工具；
4. 和测试同学对齐业务场景，梳理回归用例，落地自动化用例，协助团队接入平台；
5. 编写使用文档，给团队做操作培训，解决使用过程中的问题。

**R 结果**：
1. 核心业务接口实现定时巡检，版本回归人力减少，提前发现多起接口参数变更问题；
2. APP核心流程自动化巡检落地，版本冒烟不需要全部人工操作；
3. 自研小工具被团队高频使用，减少重复手工操作，提升整体测试效率。

## 项目二：新东方在线｜APP移动端+H5功能测试
**S 情境**：
公司面向C端的移动端产品，包含原生APP以及内嵌大量H5页面，迭代节奏快，多机型、多版本兼容性问题较多。

**T 任务**：
负责APP原生、H5页面的功能测试、兼容性测试，保障版本上线质量，发现前端、接口侧缺陷。

**A 行动**：
1. 参与需求评审，梳理测试点，编写测试用例；
2. 覆盖APP原生功能、H5页面交互、多机型适配、异常场景；
3. 执行回归测试，提交bug，跟进缺陷闭环；
4. 把高频回归场景沉淀到自动化平台，减少重复手工测试。

**R 结果**：
保障多个版本稳定上线，提前发现大量兼容性、交互类缺陷，将重复用例转为自动化，降低后续版本回归成本。

## 项目三：零氪科技（北京）有限公司｜测试平台开发（接口巡检平台，独立负责部署、发版，内部提效小工具）
**S 情境**：
团队需要一套测试平台,需要包含接口巡检平台，用于日常迭代的接口回归，需要统一内部提效工具,方便大家使用。

**T 任务**：
负责测试平台全平台功能开发，接口巡检平台开发,开发内部提效小工具赋能测试团队;同时全权承担测试平台服务器部署、版本打包、上线发版。

**A 行动**：
1. SpringBoot开发接口巡检平台，实现用例管理、定时任务、执行报告；
2. 负责服务器环境配置、项目打包、部署、版本迭代发版，处理部署过程中的异常；
3. 根据团队痛点开发各类提效小工具，解决测试人员重复造数据、核对数据的工作；
4. 维护线上平台，处理运行异常，更新文档，支持团队日常使用。

**R 结果**：
平台稳定在内网持续运行，支撑团队日常接口回归；自研工具落地，减少大量手工重复操作，解放测试人力。

## 项目四：零氪科技（北京）有限公司｜APP+H5+Web端功能测试
**S 情境**：
业务同时覆盖APP移动端、H5页面、Web后台管理端，多端同步迭代，端与端之间数据联动，容易出现一致性bug。

**T 任务**：
负责多端的功能测试，覆盖业务流程、边界场景，保障多端数据一致性，保障版本上线质量。

**A 行动**：
1. 需求评审，拆解多端业务逻辑，编写完整测试用例；
2. 执行APP、H5、Web后台的功能、边界、异常场景测试；
3. 提交缺陷，推动开发修复，回归验证；
4. 将重复回归场景沉淀到自研测试平台做自动化巡检。

**R 结果**：
多个业务版本顺利上线，多端数据一致性问题提前识别，部分回归工作交给自动化完成。
